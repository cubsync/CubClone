# 界面语言（中英）

产品只有中文、英文两套界面，**任何面向用户的文字都必须同时有两份**。中文改了，英文同一提交里一起改。

## 规则

1. 文案只放 `app/res/values/strings.xml`（中文）与 `app/res/values-en/strings.xml`（英文），键名一一对应、数量相等。
2. Java 里不许写中文/英文字面量当界面文案：用 `getString(R.string.xxx)`。日志、shell 契约、Magisk 模块脚本正文不算界面文案。
3. 布局、菜单、清单里的文字用 `@string/...`，不许写死（`android:text` / `android:title` / `android:label` / `contentDescription` 都算）。
4. 每个 Activity 必须覆盖 `attachBaseContext` 走 `Locales.wrap(base)`，否则该页会用系统语言——这是「切英文后某页整页中文」的唯一成因。
5. 需要 Context 却又不能用 Activity 的地方（后台任务、通知、默认名字）用 `Locales.wrap(c)`，**不要** `getApplicationContext()`：后者是系统语言的 Configuration。
6. shell 层只回错误码（`ERR_NEED_ROOT` / `ERR_NO_PERM` / `ERR_SHIZUKU_SVC` / `ERR_NEWPROC` / `ERR_EXT_OWN` 等），
   界面层用 `Err.text(ctx, raw)` 翻成当前语言。错误码保留 `ERR` 前缀，`startsWith("ERR")` 的判定依赖它。

## 检查

构建前自动跑，不通过直接失败：

```bash
python tools/check-i18n.py          # 键对齐 + 英文侧无中文；Java 硬编码中文给警告
python tools/check-i18n.py --strict # 硬编码中文也算失败（发版前用）
```

`CloneStore.java` 里的 Magisk 模块脚本正文在 `HARD_OK_FILES` 白名单内，不参与检查。
