## 下载

- `CubClone-0.7.1-arm64-v8a.apk` —— 绝大多数手机用这个
- `CubClone-0.7.1-universal.apk` —— 32 位设备，或不确定机型架构时用

列出与操作分身需要 Root 或 Shizuku（shell 权限）。

## 新增

- **备份 / 还原后恢复运行的应用**（Root 功能页，默认开启）：备份和还原都会先停止应用，
  全部跑完再把**当时正在使用**的应用依次打开；只认真正打开过界面的应用，
  后台推送常驻的不算。主界面长按的单条备份 / 还原同样生效。
- **备份 / 恢复包含自己**：备份时把自己排在最后且不停止自己；恢复自己时交给后台脚本跑，
  换完数据自动把界面拉回来。
- 重开应用前先提示「正在重新打开 N 个应用」，打开完自动回到 CubClone。

## 修复

- **跨空间恢复报「成功」但数据没落地**：包里带 APK 时会先装包，而这时数据目录的属主
  还是来源空间的，包管理器当成脏数据清空。现在换完目录先改属主再装包。
- **0.7.0 备份全部失败（`ERR_PACK`）**：用了系统 tar 不支持的参数，四条降级路径全挂。
  已改成按原路径收包，0.7.0 之前备的包仍然可以恢复。
- 恢复时旧数据目录挪不走会变成 `<数据目录>/<包名>/…` 的套娃，现在挪不走就先清空再换位。
- 开了「管理非自建空间」后，系统自带的分身仍然不出现在任何目标选择里；现在会列出并标注「非自建」。
- 主空间应用点了却弹「选择打开方式」（系统自带分身的机型），现在有 root / Shizuku 时直接进主空间。
- 备份后重开把后台常驻应用也当成「在用」，一次弹出一串界面；现在要求真的有界面才算。
- 网格视图切到空的分类页签时，「最近打开」跟着消失。

## 注意

- 恢复是覆盖式的：会先停止目标空间的应用，再用包里的数据替换它的数据。
- 「备份 / 还原后恢复运行的应用」只重开备份前真的在用（有界面）的应用，默认开启，
  可在 Root 功能页关掉。

## Downloads

- `CubClone-0.7.1-arm64-v8a.apk` — for most phones
- `CubClone-0.7.1-universal.apk` — for 32-bit devices, or if you are unsure

Listing and managing clones requires Root or Shizuku (shell permission).

## Added

- **Reopen apps after backup / restore** (Root features page, on by default): both backup and
  restore stop apps first, then reopen the ones that were actually in use — only apps with a
  visible UI count, background push services are ignored. Long-press single backup / restore
  on the main screen behaves the same.
- **Back up / restore CubClone itself**: it is queued last and never stopped while backing up;
  restoring itself runs from a detached script and brings the UI back when done.
- A short "reopening N apps" hint before apps are relaunched, and the app returns to CubClone
  afterwards.

## Fixed

- **Cross-space restore reported success while no data was restored**: when the archive contains
  an APK it was installed first, and the data directory still belonged to the source space's uid,
  so PackageManager wiped it as stale. Ownership is now fixed before the install step.
- **Every backup failing in 0.7.0 (`ERR_PACK`)**: it used a tar option the system tar does not
  support, so all fallbacks failed. Archives are now packed with original paths, and older
  backups remain restorable.
- Restoring could nest data as `<data dir>/<package>/…` when the old directory could not be moved;
  it is now cleared first.
- System-provided clone spaces still did not show up in target pickers even with
  "manage non-owned spaces" enabled; they are listed and marked now.
- Tapping a main-space app could pop a "open with" chooser on some ROMs; with root / Shizuku it
  now goes straight into the main space.
- Relaunch after backup treated background-only apps as "in use" and opened a string of screens;
  only apps with a real UI count now.
- "Recently opened" disappeared when switching to an empty category tab in grid view.

## Notes

- Restore is destructive: the target space's app is stopped and its data replaced by the archive.
- "Reopen apps after backup / restore" only reopens apps that had a UI before the job started.
  It is on by default and can be turned off on the Root features page.
