# 「分身」类项目清单：谁在用多用户/profile 这套原理

我们用的是 AOSP 的 `profile.CLONE`（clone profile）。下面按原理分组，最后一列写它们怎么应付「新档案被灌一整套应用」。

## A. AOSP / 官方

| 项目 | 原理 | 会不会被灌全量 | 怎么处理 |
| --- | --- | --- | --- |
| **Private Space**（Android 15+） | 独立 profile，用户类型 `android.os.usertype.profile.PRIVATE`，与 `profile.CLONE` 可共存 | 会（同样是"往新 profile 装一份应用"） | 不删：靠启动器只显示私有空间容器、锁定即 `stop-user`，用户根本看不到那堆系统应用；启动器需 `ACCESS_HIDDEN_PROFILES` + HOME role |
| **`profile.CLONE`**（我们） | `createProfileForUser(..., profile.CLONE, ...)` | 会（红米 184 包 / OP12 25 个三方） | 只能事后处理：`pm uninstall --user` 或 `pm disable-user --user` |

## B. 开源 App（work profile 路线）

| 项目 | 原理 | 有什么特权 | 怎么处理那堆应用 |
| --- | --- | --- | --- |
| **Island**（oasisfeng/island，开源） | managed profile（工作资料），Clone = `installExisting` 进 profile | 走 `ACTION_PROVISION_MANAGED_PROFILE` 拿到 **PROFILE_OWNER** | **不删，改隐藏**：`DevicePolicyManager.setApplicationHidden(true)`（freeze）、`setPackagesSuspended()`（挂起）；不丢数据、一键恢复 |
| **Shelter**（PeterCxy/Shelter，开源） | 同上，工作资料 + 文件穿梭 | 同上（PROFILE_OWNER） | 同上：freeze = `setApplicationHidden` |
| **Insular**（Shelter 的 fork，F-Droid） | 同上 | 同上 | 同上 |
| **Test DPC**（Google 官方示例） | managed profile 参考实现 | 同上 | 用来演示 DPM 能力，不做清理 |

## C. 虚拟引擎（不建用户，所以压根没这问题）

| 项目 | 原理 | 代价 |
| --- | --- | --- |
| **VirtualApp**（asLody，开源） | 在自己进程里 hook AMS/PMS，直接加载目标 APK | 兼容性差，容易被风控识别 |
| **VirtualXposed**（开源） | 同上 + Xposed | 同上，金融类基本跑不起来 |
| **DroidPlugin**（奇虎 360，开源） | 同上 | 已停更 |
| **Parallel Space / 双开助手**（闭源） | 同上（商业版） | 广告、延迟、检测风险 |

## D. 改包名重打包

| 项目 | 原理 | 代价 |
| --- | --- | --- |
| **App Cloner**（闭源付费） | 解包 APK 改 `packageName` 重签，装成另一个应用 | 每次升级要重打、可能被检测、存储不共享主身份 |

## E. Root / 系统级

| 项目 | 原理 |
| --- | --- |
| Magisk 模块、Xposed/Zygisk 分身模块、XinCif2 | 直接改 framework/PMS，绕过"建用户就全装"的限制 |

## 结论

1. **没有任何一个开源项目靠 `pm uninstall --user` 批量删**——它们的出路只有两条：
   - **有 PROFILE_OWNER 权限**（Island/Shelter/Insular）：改成 `setApplicationHidden(true)` 隐藏，可逆、不删数据，权限来自"同意创建工作资料"这个系统弹窗；
   - **根本不建用户**（虚拟引擎、改包名）：没有灌包问题，但代价是兼容性/风控。
2. 我们手里只有 Shizuku(shell)，拿不到 PROFILE_OWNER（那是 managed profile 专属），但 `pm hide` 也不行（实测 `SecurityException: requires MANAGE_USERS`）。
3. **shell 能做的最接近 `setApplicationHidden` 的是 `pm disable-user --user <uid>`**（实测权限通过）：图标消失、不删数据、`pm enable` 一键还原。差别只是"包还装着"。
4. 所以可选路线：
   - 继续 `pm uninstall --user`：最干净（真没装），代价是误判即丢数据、每个包一次 JVM；
   - 换 `pm disable-user --user`：更安全（可逆），代价是包列表里还在，需要按 enabled 状态判断；
   - 换成工作资料 + PROFILE_OWNER：拿到 `setApplicationHidden`，但形态变成"工作资料"，和 myui 分身的观感不一样。

## 四条路线对比（我们 / Private Space / Island 一派 / 虚拟引擎）

| | 我们（clone profile） | Private Space（A15+） | Island / Shelter / Insular（work profile） | 虚拟引擎 |
| --- | --- | --- | --- | --- |
| 本质 | `profile.CLONE` | `profile.PRIVATE` | `profile.MANAGED` | 进程内 hook AMS/PMS |
| 一个应用能开几份 | 空间数份（每空间一份） | 2 份（主 + 私有） | 2 份（主 + 工作） | 不限 |
| 相册 / 文件 | **与主身份互通**（实测） | 隔离 | 隔离（可单个文件穿梭） | 共享 |
| 桌面表现 | 出现在桌面，启动器可能归到「工作分区」 | 独立容器，锁定时完全隐藏 | 带公文包标记 | 自己画图标 |
| 一键隐藏 / 锁定 | 无（只能整体 stop-user） | 有，锁定即停用户、通知不响 | 关工作资料 | 无 |
| 封号风险 | 低（不同 user 的 `ANDROID_ID`、设置都隔离） | 最低（系统功能） | 低-中（`isManagedProfile()` 可被检测，银行/游戏会拒） | 高（hook/重签易被识别） |
| 数量限制 | `mMaxAllowedPerParent`：红米 Android 16 实测 **每父用户 1、全机 3**；一加/moto 不同 | **1 个**（系统写死） | **1 个**（系统写死） | 无 |
| 依赖 | Shizuku（shell）即可 | 系统需 Android 15+ | 用户同意建工作资料，无需 root | 无 |

**怎么选**

- 要「多开账号 + 相册文件与主身份互通 + 一个空间放多个应用」→ 我们这套 CLONE 最合适。
- 要「藏起来 / 隔离敏感应用」→ Private Space（A15+）最好，其次 Island/Shelter；两者都是每应用只能 2 份、且存储隔离。
- 红米那台（Android 16）实测 `profile.PRIVATE` 是 **enabled** 的，`mMaxAllowed=1`，系统私有空间可以直接用。
